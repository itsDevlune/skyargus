# Persistent data
Migration apps/core/migrations/0001_initial.py creates Job (UUID, owner, state, kind, normalized selection, result, error, attempts, timestamps), Dispatch (one-to-one durable publication intent), Sequence (unique cache key, immutable-by-API manifest), Artifact (sequence protected FK, storage identifier, checksum, media type, size), Candidate (owner, protected sequence, JSON sky mark, optimistic revision), Report (owner, protected sequence, copied immutable evidence), Share (hashed random token, report, revocation), Review (protected report, separate reviewer session and text).

The report API has no update/delete operation. Candidate edits lock and check revisions. PostgreSQL race/constraint tests and database-enforced immutable report triggers remain required; application-level immutability is not claimed to prevent an administrator from editing SQL. Observation reprocessing versions and explicit contributor tables are not yet normalized. Files written before a failed DB commit can remain orphaned; cleanup must preserve all referenced artifacts and downloads.

Migration 0002 adds Report parent/root self-references, revision numbers and a unique (root,revision) constraint. New revision creation locks the parent, rejects stale branches with 409, and preserves the earlier snapshot. Unit tests verify the chain, immutability and cross-session rejection; actual PostgreSQL concurrency still needs execution.
